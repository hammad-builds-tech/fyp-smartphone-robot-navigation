# VERDICT — capture_fresh navigation demo (2026-09-30)

## Bottom line

**NO PASS is claimed.** The Gazebo world generated from `capture_fresh` is real and matches the
recorded video (see "Geometry" below), but the **navigation demo cannot currently be shown
physically**: the robot's commanded velocities stopped producing real world motion in this
machine session, and every earlier log-only "PASS" from tonight is **invalidated** by
Gazebo ground-truth data.

## What is honest and verified

1. **The world is the genuine reconstruction.** `realroom_capture_fresh_world.sdf` (world
   `capture_fresh`) contains 209 obstacle boxes + floor slab + walls, all generated by the
   frozen pipeline from the 30-s `capture_fresh` recording (12 frames in
   `~/FYP/realroom/capture_fresh/img/`, capture_log.csv present). Nothing was hand-placed.
   It is open in the live Gazebo GUI right now for inspection.
2. **The obstacle geometry provenance is real.** The map's two substantial structures near the
   legs — comp 65 (765 cells ≈ 1.9 m², the dominant wall segment) and comp 61 (36 cells) —
   are backed by the fused point cloud (3302 cloud points inside comp 65; median
   provenance distance 0.015 m). This remains the honest limitation: the capture only
   contains enough usable geometry for these structures; every demo leg can only detour
   these. No extra obstacles were invented to make the demo look richer.
3. **Speed fix is real and verified in /cmd_vel**: `max_speed_xy 0.15 → 0.35` was the actual
   cap; after the fix, 10 087 recorded /cmd_vel samples show median = p90 = max = 0.35 m/s.

## Why tonight's "PASS" runs are invalidated

The demo script verifies detours using **wheel odometry**. Gazebo ground truth (server-side
`dynamic_pose/info`, logged at 2 Hz into `/tmp/ve_final/gz_pose.csv`, preserved at
`evidence/logs/finalrun_phantom/gz_pose_PROVES_PHANTOM.csv`) shows:

- The robot **physically wedged at (6.40, 17.20) early in leg 1** — gz truth frozen there
  for the entire rest of the run, while odometry kept integrating wheel slip.
- odometry path length: 28.0 m; **physical** path length: 5.6 m.
- odometry believed it reached all three goals (x down to 0.24); the robot **never
  physically traveled west of x ≈ 6.39**.
- Therefore "MULTI-GOAL DEMO: PASS" (3 legs, detour ratios, 0.35 m/s) was a **phantom PASS**:
  Nav2 drove a robot that existed in odometry, not in the world. `MULTI-GOAL DEMO: PASS`
  in tonight's `multi_demo.log` is NOT valid evidence.

The overlay images built from that run (map_view / traj_on_frames / detour_panel) were moved
to `evidence/logs/finalrun_phantom/` and must not be presented as evidence.

## The new failure, isolated

After (and independent of) the wedge, the robot stopped responding to commands physically:

- Fresh robots (2 additional spawns, one dropped from 1.5 m to force settling): 0.038–0.054 m
  movement for 0.9 m expected.
- Completely fresh boot + fresh stack + traction gate: gate FAILED (0.002 m displacement).
- Sim-server-only restart: 0.079 m for 0.9 m expected.
- GUI/perception/backend SIGSTOPped (CPU freed): no change → not CPU starvation.
- RTF stays 1.0; DiffDrive receives the twists (verified on gz /cmd_vel); no world geometry
  within 0.6 m of the stall points (209 boxes scanned); robot upright, z = 0.280.
- Earlier today the SAME setup produced real physical motion (gz ground truth shows the robot
  physically reaching (0.25, 17.94) at 0.35 m/s before the wedge), so the degradation is
  environmental (physics/actuation layer across this machine boot), not the pipeline, the
  world, or the Nav2 config.

## Guardrail added

`/tmp/run_final2.sh` now contains a **physical traction gate**: before the demo may start it
drives 0.3 m/s for 3 s and measures real world displacement via gz ground truth (needs
≥ 0.7 m). On this boot it correctly refused to start the demo.

## What would make the demo honest

1. A machine/boot session where the traction gate passes (fresh reboot is the most likely fix;
   verify with the 15-second gate before believing anything else).
2. Then the demo can run under the existing instrumentation: gz ground-truth logger +
   /cmd_vel + odom logger, with the demo verdict cross-checked against physical displacement.
3. Accept the geometry limitation: legs detour comp 65 (+ comp 61). If more distinct obstacles
   are wanted, a new capture with more of the room is needed — not synthetic ones.
